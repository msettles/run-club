# Release 1.6.0

November 13, 2026. Git tag: `1.6.0`.

This release records the completed launch fixes, security rules, tests, approved artwork and operational documentation in one reproducible source checkpoint. The production build must be made after the release commit so its displayed commit matches the tag.

## Resulting behavior

- Claimed historical names contribute each shared dated run once. Separate canonical runs and additive undated credits remain intact; app attendance overlapping claimed history does not add a duplicate run.
- Run IDs and dates identify attendance. Code words validate check-in only. Special-event credit follows the reviewed explicit tags; blank tags give none.
- A persisted maintenance switch pauses member/organizer mutations while retaining validated admin scheduling/import/reconciliation access. Scheduling explains maintenance refusals instead of incorrectly calling them code-word locks.
- Claim merchandise work survives interruptions and retries without replacing fulfilled alerts. Admin recomputation reconciles existing claims, standings and attendance-backed rewards.
- The offline app shell excludes Firebase reserved authentication pages, allowing Google sign-in to complete. Current approved icon/splash assets are preserved, with additional approved artwork sources/previews included.
- Setup, permissions, import, backup and launch guides distinguish current behavior, historical audits, owner-confirmed acceptance and future proposals.

## Validation

Release checks use Node 24.22.2. Store integration and rules emulator suites run sequentially on port 8085.

- 221 unit tests, 47 store integration tests, 77 security-rule/seed checks and 7 resolver checks.
- 30 browser checks across Chromium and mobile WebKit.
- App/browser type checks, production and calendar-function builds, and lazy bundle checks.
- ESLint: zero errors; existing warnings remain. Dependency audit: zero vulnerabilities.
- Local Markdown links, code fences and operational npm commands checked.

## Deployment scope

Deploy hosting and Firestore rules together to the existing Woodland project. The calendar function's source is unchanged; its build is verified, and the existing server remains in place. Verify live build/commit assets and rules against the tagged release after deployment.

This release does not rerun the completed data reset/import, change maintenance, create attendance, alter routes/accounts/claims or enable paid backups. Billing alerts were configured separately at the owner's request. Private exports, backup/verification artifacts, credentials and account-specific one-off cleanup scripts are excluded from Git.

The [readiness review](../go-live-readiness-review.md) records completed owner acceptance; [documentation status](../documentation-status.md) separates accepted checks, owner decisions and future proposals.
